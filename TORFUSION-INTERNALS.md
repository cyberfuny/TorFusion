# TorFusion: как всё работает внутри

Этот документ описывает текущую реализацию TorFusion: TUI, Tor ControlPort,
transparent mode, firewall, автоматическую ротацию IP и постоянный systemd-
режим.

## 1. Общая схема

TorFusion состоит из одного Go-бинарника, который может работать в двух
режимах:

1. **TUI-настройщик** — интерактивное меню для запуска, остановки, диагностики
   и сохранения параметров.
2. **Фоновый daemon** — тот же бинарник без TUI, запущенный systemd. Он
   применяет маршрутизацию, поддерживает её после выхода из TUI и запускается
   после перезагрузки.

Сетевой путь в transparent mode:

```text
Приложение
    ↓
iptables TORFUSION / TORFUSION_NAT
    ↓
Tor TransPort 127.0.0.1:9040
Tor DNSPort   127.0.0.1:5353
    ↓
Tor SOCKS5    127.0.0.1:9050
    ↓
Tor network → exit node → Интернет
```

Политика transparent mode — **Tor-only для поддерживаемого IPv4-трафика**:
TCP уходит в Tor TransPort, DNS UDP/53 — в Tor DNSPort, а другой UDP и
неподдерживаемые протоколы блокируются, чтобы они не вышли напрямую.
IPv6 блокируется fail-closed отдельными цепочками `ip6tables`: текущий
transparent path TorFusion не направляет IPv6 в IPv4-порты Tor.

Для смены цепочки используется Tor ControlPort `127.0.0.1:9051` и команда
`SIGNAL NEWNYM`.

## 2. Запуск TUI

Обычный запуск:

```bash
sudo ./torfusion
```

Root нужен для операций, которые меняют `/etc/tor/torrc`, читают
`iptables-save`, создают firewall-правила или управляют systemd. Диагностические
операции вроде получения IP могут работать без root, если Tor уже запущен.

Вверху TUI отображается компактный заголовок:

```text
◈ TORFUSION // ONION NETWORK CONTROL ◈
```

Нижняя строка показывает результат последней операции, состояние маршрутизации,
режим, страну, текущий IP и интервал авто-ротации. Следующая строка содержит
подсказки клавиш.

## 3. Пункты меню TUI

Пункты обрабатываются в `model.execute(index)`. Долгие операции запускаются как
Bubble Tea-команды, поэтому интерфейс не должен блокироваться во время
сетевых запросов или операций systemd.

### 3.0. «Авто-ротація IP»

Это не отдельный экран: пункт расширяет существующий выбор интервала. Быстрые
варианты задают фиксированные интервалы, а пользовательский ввод принимает:

```text
5m       фиксированная задержка пять минут
30-120   случайная задержка от 30 до 120 секунд
30s-2m   тот же диапазон с единицами времени
```

Поддерживаются `s`, `m`, `h`, `d`, а максимальная задержка составляет 86400
секунд. Старый параметр `interval_seconds` автоматически преобразуется в
одинаковые `interval_min_seconds` и `interval_max_seconds`. Ротация всегда
продолжается без ограничения количества смен, пока её не отключить.

### 3.1. «Увімкнути прозору маршрутизацію Tor»

Что происходит:

1. Проверяется, что TUI запущен от root.
2. Сохраняются конфигурация и текущий бинарник.
3. Автоматически устанавливаются бинарник и systemd-unit.
4. Запускается или перезапускается фоновый TorFusion daemon.
5. Daemon проверяет Tor и доступность его SOCKS5-порта.
6. Если Tor ещё не готов, обновляется управляемый блок в `/etc/tor/torrc`.
7. Выполняется `tor --verify-config`, запускается `tor@default` и проверяется
   внешний IP.
8. В transparent mode создаётся резервная копия через `iptables-save` и
   `ip6tables-save`.
9. Создаются и заполняются IPv4-цепочки `TORFUSION`, `TORFUSION_NAT`,
    `TORFUSION_FORWARD` и `TORFUSION_NAT_FORWARD`.
10. Создаются IPv6-цепочки `TORFUSION6` и `TORFUSION_FORWARD6`; они
    разрешают loopback и локальные IPv6-сети, а
    внешний IPv6-трафик отклоняют.
11. В TUI отображается внешний IP, полученный через Tor SOCKS5.

Daemon выбирает задержку через `interval_min_seconds` и
`interval_max_seconds` перед каждой ротацией и продолжает работу без лимита,
пока сервис не остановлен или ротация не отключена.

В `proxy` mode firewall не изменяется. Tor запускается и настраивается, но
приложения должны использовать SOCKS5 `127.0.0.1:9050` самостоятельно.

Если `iptables-save` или `ip6tables-save` возвращает `Permission denied`,
приложение останавливает
операцию до изменения firewall. Запускать transparent mode нужно через `sudo`.

### 3.2. «Зупинити маршрутизацію / очистити правила»

Что происходит:

1. Проверяется root-доступ.
2. Извлекается jump из `OUTPUT` в `TORFUSION`.
3. Извлекается jump из `nat OUTPUT` в `TORFUSION_NAT`.
4. Извлекается jump из `FORWARD` в `TORFUSION_FORWARD`.
5. Извлекается jump из `nat PREROUTING` в `TORFUSION_NAT_FORWARD`.
6. Цепочки очищаются.
7. Цепочки удаляются.
8. Удаляются IPv6 hooks и цепочки `TORFUSION6` и `TORFUSION_FORWARD6`.
9. TorFusion больше не перенаправляет трафик.

Системная служба Tor при этом не обязательно останавливается. Если нужно
остановить и Tor:

```bash
sudo systemctl stop tor@default
```

### 3.3. «Змінити Tor-ланцюжок»

Пункт подключается к ControlPort `9051`, читает cookie-авторизацию из одного из
путей:

```text
/run/tor/control.authcookie
/var/lib/tor/control_auth_cookie
```

Затем отправляются:

```text
AUTHENTICATE <cookie>
SIGNAL NEWNYM
```

После запроса приложение ждёт несколько секунд и получает новый внешний IP через
Tor SOCKS5. Tor не обязан менять IP мгновенно: новая цепочка создаётся с учётом
ограничений Tor и политики exit-ноды.

### 3.4. «Авто-ротація IP»

Открывает отдельный выбор интервала. Доступны:

```text
вимкнено
30 секунд
1 хвилина
5 хвилин
15 хвилин
кастомне значення
```

Для кастомного значения вводятся секунды от `1` до `86400`.

Пользовательский ввод также поддерживает:

```text
5m       фиксированный интервал пять минут
30-120   случайный интервал от 30 до 120 секунд
30s-2m   случайный интервал от 30 секунд до двух минут
```

Ротация не имеет ограничения по количеству смен. Она продолжается, пока
интервал не будет установлен в `вимкнено`, сервис не будет остановлен или
конфигурация не будет изменена.

Управление:

```text
i или Enter на пункте       открыть выбор
↑/↓ или j/k                 выбрать значение
Enter                       сохранить
Esc                         отменить
```

Значение записывается в JSON/YAML-конфигурацию. `0` означает, что постоянная
маршрутизация разрешена, но автоматическая смена цепочек выключена.

В обычном TUI таймер живёт внутри процесса TUI. Поэтому после выхода из TUI
обычная TUI-ротация прекращается. Для постоянной ротации нужно включить
фоновой режим из меню.

### 3.5. «Оновити статус»

Выполняется запрос к Tor Project API через локальный SOCKS5:

```text
https://check.torproject.org/api/ip
```

Результат — внешний IP текущей Tor-цепочки. Он может отличаться от IP другого
сайта, потому что разные запросы могут использовать разные Tor circuits.

### 3.6. «Перевірити DNS-витік»

Сейчас выполняется команда:

```bash
curl --socks5-hostname 127.0.0.1:9050 \
  --max-time 15 \
  https://1.1.1.1/cdn-cgi/trace
```

Параметр `--socks5-hostname` передаёт разрешение имён через SOCKS5. Ответ
Cloudflare содержит поле `ip`, которое является внешним IP, увиденным
Cloudflare, а не адресом DNS-сервера.

Этот пункт является диагностикой SOCKS5/Cloudflare и не заменяет полный аудит
DNS-утечек всех приложений системы.

### 3.7. «Показати статус служби Tor»

Выполняется:

```bash
systemctl is-active tor@default
```

В TUI отображается состояние systemd, например `active`, `inactive` или
сообщение об ошибке.

### 3.8. «Показати журнали Tor»

Читаются последние записи:

```bash
journalctl -u tor@default -n <log_lines> --no-pager
```

В компактной строке TUI показывается последняя строка журнала. Полный вывод
доступен через CLI или `journalctl`.

### 3.9. «Зберегти конфігурацію»

Конфигурация записывается в путь, с которым запущен TUI:

```text
~/.config/torfusion/config.json
```

Путь можно изменить через `TORFUSION_CONFIG` или `--config`. Файл создаётся с
правами `0600`, каталог — с правами `0700`.

Сохраняются:

```json
{
  "interval_seconds": 300,
  "interval_min_seconds": 300,
  "interval_max_seconds": 300,
  "country": "auto",
  "kill_switch": true,
  "mode": "transparent",
  "log_lines": 100
}
```

### 3.10. «Увімкнути фоновий режим»

Этот пункт выполняет автоматическую установку постоянного режима. После первой
кнопки запуска маршрутизации отдельно нажимать его не нужно:

1. Сохраняет текущий TUI-конфиг.
2. Копирует текущий бинарник в:
   `/usr/local/bin/torfusion`.
3. Копирует конфиг в:
   `/etc/torfusion/config.json`.
4. Создаёт:
   `/etc/systemd/system/torfusion.service`.
5. Выполняет `systemctl daemon-reload`.
6. Выполняет `systemctl enable --now torfusion.service`.

После этого TUI можно закрыть. Ротация, если интервал больше нуля, выполняется
уже daemon-процессом, а не TUI.

Если интервал равен `0`, daemon поддерживает маршрутизацию без автоматической
ротации. Интервал не является обязательным.

### 3.11. «Вимкнути фоновий режим»

Этот пункт:

1. Выполняет `systemctl disable --now torfusion.service`.
2. Очищает цепочки и jumps TorFusion.
3. Удаляет установленный unit-файл.
4. Удаляет `/usr/local/bin/torfusion`.
5. Удаляет `/etc/torfusion/config.json`.
6. Выполняет `systemctl daemon-reload`.

Системную службу Tor и пакет TorFusion он не удаляет. Удаляется только
установленный постоянный режим TorFusion.

## 4. Фоновый daemon

Daemon запускается той же программой:

```bash
sudo ./torfusion --action daemon --config /etc/torfusion/config.json
```

При запуске daemon:

1. Загружает конфигурацию.
2. Запускает или проверяет готовность Tor.
3. Применяет выбранный режим маршрутизации.
4. Если интервал равен `0`, ждёт сигнал остановки.
5. Если интервал больше нуля, создаёт timer.
6. По срабатыванию timer отправляет `SIGNAL NEWNYM`.
7. При ошибке ротации пишет сообщение в systemd journal и продолжает работу.
8. При остановке очищает firewall в transparent mode.

Важно: daemon не меняет конфигурацию по изменениям TUI автоматически. После
изменения настроек нужно снова выбрать **«Увімкнути фоновий режим»**. Это
перезапишет системный конфиг и перезапустит сервис.

## 5. Systemd

Unit-файл содержит:

```ini
After=network-online.target tor@default.service
Wants=network-online.target tor@default.service
Restart=on-failure
RestartSec=5
User=root
```

Это означает:

- запуск после сети и попытка запуска Tor;
- остановка Tor не останавливает TorFusion: его firewall-правила остаются
  активными, поэтому kill switch блокирует трафик до восстановления Tor;
- запуск с root-правами;
- автоматический перезапуск daemon после сбоя;
- запуск после перезагрузки, если сервис был включён.

Проверка:

```bash
sudo systemctl status torfusion.service
sudo journalctl -u torfusion.service -f
```

## 6. CLI

Одноразовые действия:

```bash
sudo ./torfusion --action start
sudo ./torfusion --action stop
sudo ./torfusion --action rotate
./torfusion --action ip
./torfusion --action status
./torfusion --action dns
./torfusion --action logs
```

Постоянный режим:

```bash
sudo ./torfusion --install
sudo ./torfusion --uninstall
```

Параметры:

```text
--action     start, stop, rotate, daemon, ip, status, dns или logs
--country    код страны exit-ноды, например de
--interval   фиксированный интервал в секундах; 0 отключает авто-ротацию
--config     путь к JSON/YAML-конфигурации
--install    установить и запустить systemd-режим
--uninstall  остановить systemd-режим и очистить правила
```

## 7. Firewall и kill-switch

В transparent mode TorFusion использует только собственные цепочки:

```text
TORFUSION
TORFUSION_NAT
TORFUSION_FORWARD
TORFUSION_NAT_FORWARD
TORFUSION6
TORFUSION_FORWARD6
```

Локальный трафик подключается к `OUTPUT`, а forwarded-трафик — к `FORWARD` и
`PREROUTING`. Для forwarded-трафика используется отдельная цепочка, потому что
match `owner` применяется к локальному `OUTPUT`, но не к forwarded-пакетам.

Tor не является прозрачным UDP-прокси. Поэтому UDP/53 сначала перенаправляется
в `DNSPort`, а другой UDP явно отклоняется. Финальная политика также блокирует
любой оставшийся неподдерживаемый внешний трафик.

Перед изменением правил создаётся резервная копия `iptables-save`. Если Tor не
готов, резервная копия не создаётся или не удаётся очистить существующую цепочку,
новые правила не применяются. При ошибке добавления правила TorFusion пытается
удалить свои jumps и цепочки, чтобы не оставить частично активную конфигурацию.

IPv6 не перенаправляется в Tor: цепочки `TORFUSION6` и
`TORFUSION_FORWARD6` разрешают только loopback и локальные
`fc00::/7`/`fe80::/10`, а внешний IPv6 отклоняют. Отдельного обхода для уже
установленных соединений нет: kill switch блокирует и их после остановки Tor. Это намеренная
fail-closed политика, поскольку текущие IPv4 `TransPort` и `DNSPort` не
являются IPv6 transparent proxy.

При `kill_switch: true` финальные правила цепочек `TORFUSION` и
`TORFUSION_FORWARD` отклоняют
неразрешённый трафик. Это защищает от прямого выхода, но при остановке Tor
может заблокировать сеть. Поэтому сначала выключайте TorFusion:

```bash
sudo ./torfusion --uninstall
```

или выберите в TUI «Вимкнути фоновий режим», а уже потом останавливайте Tor.

Аварийное восстановление:

```bash
sudo ./restore.sh
```

Не используйте без необходимости глобальные команды `iptables -F` и
`iptables -X`: они могут удалить правила других программ.

`restore.sh` удаляет только hooks и цепочки TorFusion, включая IPv4 и IPv6.
После подтверждения он также перезапускает NetworkManager (или networking) и
останавливает `tor@default`; это аварийный сценарий, а не обычная команда
«остановить маршрутизацию».

## 8. Проверка и тестирование

Минимальная проверка:

```bash
go test ./...
go vet ./...
go build -o torfusion .
```

Дополнительные проверки:

```bash
go test -race ./...
go test -cover ./...
systemd-analyze verify torfusion.service
```

Unit-тесты покрывают конфигурацию, firewall-цепочки, kill-switch,
идемпотентную очистку, проверку системных команд и timeout-контексты.

## 9. Ограничения и безопасность

- Tor не гарантирует одну и ту же exit-ноду для разных сайтов.
- IP, показанный разными сервисами, может отличаться.
- `SIGNAL NEWNYM` просит Tor создать новую цепочку, но не гарантирует
  мгновенную смену IP.
- DNS-тест Cloudflare не является полным аудитом DNS всей системы.
- Transparent mode требует root и может повлиять на сеть.
- `country` принимается только как `auto` или две латинские буквы. Переводы
  строк, пробелы, `{`, `}`, `#` и другие символы отклоняются до записи в
  `/etc/tor/torrc`.
- Не включайте firewall-режим на удалённом сервере без консольного доступа.
- При kill-switch сначала отключайте TorFusion, затем останавливайте Tor.
- Фоновый daemon должен использовать конфиг из `/etc/torfusion/config.json`,
  который устанавливается через TUI или `--install`.
